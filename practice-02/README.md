## 4. Модель данных и функции

**Модель задачи** - плоский объект из четырёх полей: id (положительное безопасное целое), title (строка 1-100 символов после trim), completed (boolean, при создании всегда false), priority ("low" / "medium" / "high", по умолчанию "medium").

**Файлы:** src/data.js хранит общие и вариантные данные без логики; src/task-service.js содержит девять прикладных функций без вывода и без чтения данных извне; src/main.js импортирует данные и функции и выполняет общий и индивидуальный сценарии; checks.js - готовые проверки.

**Формат результатов:** функции создания/изменения возвращают {ok: true, task} или {ok: true, tasks} при успехе и {ok: false, error} при отказе; функции чтения возвращают объект, массив или undefined без объекта ошибки.

**Почему id не равен индексу:**

Индекс - текущая позиция элемента в массиве (0, 1, 2, …). Он меняется при удалении и вставке: после удаления id=7 элементы сдвигаются, и id=10 может оказаться на индексе 2 вместо 3. id - стабильный идентификатор, он не меняется при операциях над соседними элементами. В общем наборе id равны 1, 4, 7, 10 - попытка tasks[7] вернула бы undefined, хотя задача с id=7 существует (по индексу 2). Поэтому поиск идёт через find по полю id, а не через обращение по индексу.

**Почему getTaskStats возвращает число, а не строку с процентом:**

Функция расчётная: её результат используется и для сравнений, и для вычислений, и для вывода. Строку "50.0%" нельзя сравнивать с числом или складывать. toFixed(1) возвращает строку и является операцией отображения, поэтому применяется в main.js, а не внутри расчёта. progress возвращается без предварительного округления - например, 33.3333333333, а при выводе превращается в "33.3%".

**Какие объекты копируются при изменении задачи:**

При изменении одной задачи создаётся новый массив (spread / map / filter) и новый объект только для изменяемой записи - через { ...task, поле: новоеЗначение }. Остальные записи переиспользуются: их объекты не изменяются, и копировать их не нужно. Модель плоская - все поля примитивные, вложенных объектов нет, поэтому глубокое копирование не требуется.

## 9. Вывод

По сравнению с ПР1 код разделён на ES-модули: данные вынесены в data.js, прикладные функции - в task-service.js, сценарий и вывод - в main.js. Возвращаемые значения используются везде, где раньше был только console.log: функции возвращают объект результата {ok, task/tasks} или {ok: false, error}, а решение о выводе принимает main.js. Неизменность данных проверена сравнением demoTasks до и после сценария, а также проверками checks.js с замороженными (Object.freeze) входными объектами - ни одна операция не изменила исходные записи. В процессе работы пришлось исправить пропущенный return в стрелочной функции эксперимента 2 и следить за порядком spread при обновлении задач: {...task, title: ...}, а не {title, ...task}, иначе старое значение перекрывало новое.
